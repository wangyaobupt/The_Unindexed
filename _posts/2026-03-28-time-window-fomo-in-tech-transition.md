# 时间窗口里的工作法：关于速度、价值与一种逐渐成形的判断

这段时间，我越来越频繁地感到一种奇怪的张力。

## 一个并不均匀的现实

当下围绕 AI Agent 的讨论里，常常会出现一种强烈判断：它不只是提升效率的工具，而是会系统性改写大部分知识工作，甚至包括探索性工作。

但如果稍微拉开一点视角，就会发现这个世界其实是分层的。

像 Claude Code、Codex 这样的生产力工具，进入“可用状态”大概已有一年左右，但它们的扩散远没有想象中那么快。真正把 AI 稳定纳入生产流程的人，依然只是很小一部分；更多人只是知道这些工具、偶尔试用过 chatbot，甚至还几乎没有接触过AI。

这和我的体感很接近。即便是在软件行业，真正把这类工具变成日常工作方式的人，也远没有形成主流。

前段时间，我给一个大约百人规模的软件团队做过一次相关分享。按理说，这已经是最容易率先采用这类工具的一群人了，但现场给我的感受仍然是：真正把它们稳定纳入生产流程的人，依然只是少数。更多人要么听说过，要么试过几次，要么还停留在“我知道它很强，但还没真正变成我的工作方式”的阶段。

就连我自己，也不是一开始就进入这种状态的。我也是先经历了非 Agent 工具的阶段，再进入 Agent mode，最后才逐步变成高强度使用者。回头看，这更让我觉得：这场扩散不是开关式的，而是分层的、分阶段的，也是高度不均匀的。

如果用一句话总结这个阶段的事实，那就是：工具已经出现，但扩散极不均匀。

## 同一个事实，会长出三种叙事

也正因为如此，同一个事实，会自然生长出几种截然不同、但都很有煽动力的叙事。

第一种是超额收益叙事。它的逻辑非常简单：既然别人还没学会，而你已经会了，那现在就是抢时间、抢产出、抢位置的时候。你应该尽可能多做，尽可能快做，直到这种 edge 被市场抹平。这套说法很像投资世界里的窗口期思维。有 edge 的时候，不应该慢吞吞地精打细算，而应该尽可能多找几个盆去接水。

第二种是上瘾叙事。这也不难理解。一个人第一次遇到这种工具时，很容易被击中。因为它不像传统软件那样只是被动执行命令，而像是一个随时待命的协作对象。它能理解意图，能调用知识，能跟着你的问题一路追下去。哪怕它经常犯错，只要你真正体验过那种“想法刚形成，就能立刻开始外化”的速度感，你就很难不兴奋。它确实像某种智力层面的网游，很容易越用越上头。

但我越来越倾向于第三种叙事，也就是工具叙事。

Agent 仍然是工具，不是魔法。它的强大是真实的，但它需要人持续支付认知成本，这一点也是真实的。你需要提出明确目标，需要监督过程，需要在关键节点纠偏，需要判断输出是否可靠。今天的 Agent 在知识密度上，已经足以在很多局部任务里达到初级工程师、研究助理，甚至更高的水平；但在“该不该做这件事”“为什么它值得被做出来”“为什么它不能只是生成一下，而必须长期可用、出了问题后仍然有人能理解、能维护、能负责”这些问题上，它还远远没有成熟到可以脱离人的判断独立运行。

如果再往前说一步，我现在越来越相信的一句话是：AI 降低的是执行成本，抬高的是问题定义的门槛。执行会越来越便宜，真正稀缺的反而是：你是否能定义一个值得解决的问题，并把它整理成一个可以被推理、被检查、被迭代推进的结构。

这也是为什么，很多看起来很激进的“全自动工作流”，在实际生产里常常会迅速暴露出问题。它们不是完全不能用，而是非常依赖操作者自己是否有足够强的判断力。没有判断力的人，得到的不是自动化，而是高速度地产出低质量结果。用 Agent 指挥 Agent，当然可以把 token 烧得非常快，也可以制造出一种规模感和繁忙感，但规模感不等于价值，繁忙感也不等于成果。

## 压力并不来自工具本身

问题在于，一旦你接受了前两种叙事，后面就会自动长出更猛烈的推论。

你会开始觉得，任何有价值的 idea 都必须立刻做出来，不然很快就会被别人做掉。你会开始觉得，时间尺度本身被改写了。以前一个像样的项目做半年，是正常的；今天你只要说“这件事需要半年”，听上去就像在宣布自己已经落后。你会不断听到类似的问题：为什么不能再快一点？为什么不能开更多并行？为什么不能让更多 Agent 连夜跑？为什么还在做“手工活”？

### 行业正在把这种压力放大

这种压力并不只存在于社交媒体上的情绪里，它也在被行业里的强势声音不断放大。大公司开始把 AI 使用纳入内部管理和绩效语言，行业领袖也在不断强化一种判断：未来高水平知识工作者，理应更高频地调用模型、更自然地消耗 token、更习惯于并行地驱动多个 Agent。

比如 Jensen Huang 在 2026 年 3 月的一次播客里就给过一个非常激进的判断：如果一个年薪 50 万美元的工程师，一年只消耗几千美元的 AI token，他会非常警惕；在他的设想里，这样的工程师至少应该消耗相当于年薪一半量级的 token。类似这样的表达，正在把 token 消耗从一种成本，慢慢推成一种投入程度、先进性，甚至职业判断力的象征。

我身边也有类似的气氛。越是和我同层级的人，越容易强调更高的 token 消耗、更大的并行规模、更强的自动化程度。好像你如果没有两个高价订阅一起打满，没有每个月烧掉数千美元 API 额度，就说明你还不够认真，或者还没有真正进入这个时代。

### 但我的实际体验并不是这样

但我的实际体验并不是这样。如果把“生产”定义为交付能稳定运行的软件，或者严谨可靠的分析报告，那么真正高质量的工作，并不只是不断增加 token 或不断叠 Agent。以我的使用方式来说，100 美元级别的订阅，或者每月 1000 美元级别的 API 成本，已经足以支撑非常高强度的工作。再往上当然也能烧得掉，可问题不在于能不能烧掉，而在于烧掉之后到底换来了什么。

如果没有质量控制，更多 Agent 和更多 token 并不会自动变成更多价值。它们当然可以制造出一种速度感、规模感、繁忙感，但这些感受本身，并不等于结果。

### 真正难处理的，是反驳之后仍然存在的绝望

这些问题最厉害的地方，不在于它们是否正确，而在于它们会慢慢进入人的自我评价系统。久而久之，你不是在回答别人，而是在怀疑自己。你明明已经每天都在用最前沿的工具，你明明已经在真实生产环境里和它们打交道，但你还是会产生一种不安全感：是不是还有别人比我更快？是不是我的工作方式太保守？是不是我已经在被新的范式甩开？

这就是技术转型期里最隐蔽的 FOMO。

它并不只发生在“没接触 AI 的人”身上。恰恰相反，它更容易发生在那些已经深度进入新工具、新流程的人身上。因为他们离前线足够近，所以更容易听见各种加速叙事的轰鸣声；也因为他们真的体验过效率提升，所以更难对“再快一点”这件事保持距离。

## 有些价值，不能被速度直接替代

我最近反复提醒自己的一件事是：必须把“快”从“价值”里拆出来。

快当然重要。任何工具革命，最先改变的都是速度。以前要一周完成的工作，现在两天就能搭出雏形；以前一个人只能推进一个方向，现在一个人可能能同时维持三到五条线索。这些变化都是真的，而且会持续改写职业竞争的地形。

但另一方面，真正重要的工作，往往并不是“再快一点”就能直接替代的。

比如我最近反复在想的一类问题：既然原始数据已经包含了人们在不同场景下决策的全部记录，且 LLM 训练中已经见过了几乎所有数据，那么为什么模型在复杂、动态、不具备完备信息的场景下，比如真实 ICU 临床，比如自动驾驶，还是做不了高质量推理？很多人以为，只要把更多上下文塞进去、把更多 Agent 并起来、把 token 预算继续拉高，问题迟早会被暴力解决。但真实世界里并不是这样。一次复杂流程留下来的原始记录，表面上信息极其丰富，真正决定判断的信号却常常被噪音、时间碎片和隐式关联埋在里面。

更麻烦的是，这类问题不是做一道有标准答案的题，而是在不确定性中不断生成假说、累积证据、排除错误路径。它没有像数学证明或测试套件那样的机械验证标准，很多时候还掺杂着没有被正式写进数据里的隐性约束。你如果没有先把这些结构看清楚，后面无论堆多少算力，都只是更快地在混乱里打转。

所以，在这种问题上，真正有价值的工作不是多开十个 Agent 去“跑”，而是先把问题重新整理成一个可以被推理、被检查、被迭代的结构：哪些信息需要被重组，哪些中间步骤必须显性化，哪些判断标准需要被单独建立出来。这样的工作当然也必须使用 AI 辅助设计和实现，但关键问题仍然需要人来解决，而且是一个有动机的人来解决：该不该做这件事，为什么它值得被做出来，为什么它不能只是生成一下，而必须长期可用、出了问题后仍然有人能理解、能维护、能负责。你不可能像说“给我一个贪吃蛇游戏”那样，期待拿到一个现成的 app；要做真正有价值的东西，你首先得定义那个价值问题本身的方向。

很多人担心的是，自己花六个月、一年做出来的东西，会不会被另一个人用 AI 三天复制掉。我现在越来越不相信这种说法了。真正可能在三天内被复制掉的，通常不是你六个月工作的核心价值，而是那些本来就更接近包装层、搬运层、整合层的部分。真正不能轻易复制的，是你在这六个月里形成的判断、取舍、审美、问题意识，以及那些只有长期贴着现实打磨才能得到的结构性理解。

## 先决定自己在玩什么游戏

所以，时间窗口当然存在，FOMO 也不是幻觉。这个时代确实在加速，谁都不能装作没看见。

但一个人真正该做的，可能不是被 FOMO 驱赶着拼命向前冲，而是先决定自己到底在玩什么游戏。如果你的目标本来就是做短平快、抢热点、拼覆盖面，那么全力追求速度没有问题。但如果你的目标是做真正有门槛的工程、建立可靠的方法、在一个复杂领域里做出别人短期复制不了的东西，那么速度只能是约束条件之一，不能升格为最高原则。

对大多数没有大公司资源、没有无限预算、也没有完整团队的人来说，这一点尤其重要。我们很可能永远都比不过某些组织的速度、算力和并行规模。既然如此，继续把自己放在那套评分系统里，只会源源不断地产生羞耻感和失败感。

不如换一个更根本的问题：我现在做的东西，是否真的值得我在未来六个月、十二个月里持续投入？如果答案是肯定的，那就做下去。至于别人是不是又快了100倍，很多时候并没有那么重要。

## 价值来自专注的积分

“价值”不会自动产生于 Token 的消耗量，也不会自动产生于一边刷信息流、一边盯着 Agent 跑任务的那种在线时长，只能来自于人类高强度认知投入（专注）在时间轴上的累积，即“专注的积分”。

$$
\text{Value} \propto \left(\int \text{Focused Cognitive Effort}\, dt\right)\cdot g(\text{Token Usage})
$$

$\int \text{Focused Cognitive Effort}\, dt$ 表示人类高强度认知投入在时间上的累积，$g(\text{Token Usage})$ 表示工具效率带来的调制作用。前者是主项，后者是乘子；没有前者，后者不会自动生成价值。
