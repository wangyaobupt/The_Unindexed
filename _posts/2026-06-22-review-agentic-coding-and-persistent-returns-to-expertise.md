前几天Anthropic发布了一篇研究报告[**“Agentic coding and persistent returns to expertise”**](https://www.anthropic.com/research/claude-code-expertise)，本文不打算做翻译或者一般性解读，而是针对其中的Findings做选择性讨论

## 1. 用户对结果的影响

### 1.1. 什么是Anthropic研究团队眼中的用户专业度，有什么实际影响

对于**某个Task中**某个用户的专业程度，基于以下维度评价

- 能否清晰地描述他们的方向(frame the direction)
- 他们让agent如何去验证
- 他们倾向于纠正agent，还是让agent纠正他们自己

这里要特别强调某个Task，即Task specific，在这份研究报告中，研究团队不是在评价用户这个人有多专业，而是在这个session（对于agent来说这就是一个task）里面，用户的行为有多专业。

毫不意外的是，对于高级别用户（level 5），agent执行了更多的工作(actions per turn), 且生成了更多的输出[Fig 3]。此外，用户专业水平越高，其任务成功率，出现错误之后能纠正回来的几率，都明显更高[Fig.5]

### 1.2 说明什么：人和Agent的生产关系是“师傅带徒弟”，不是“上下级”

我在[此前一篇文章](https://wangyaobupt.github.io/The_Unindexed/2026/04/20/the-bottleneck-of-ai-production-is-now-control.html)中提出了人和AI协作的三种模式

- 老板-顾问
- 师傅带徒弟
- 上级布置任务，下级交付结果

上面这些测量的显然不是“顾问模式”，否则就无所谓成功与失败。在真实的，需要“能运行”、“能commit”的约束下，agent要么是徒弟，要么是下级。

从上述实验结果来看，今天的主流模式仍然是“师傅带徒弟”，而不是“上级指挥下级”。因为假使是“上下级关系”，上级对于专业的下级完完全全是外行，以本文的研究视角，这样的用户一定会被划到level 1（新手），而非level 5；而现实生活中，即便上级是外行，组织仍然可能靠分工、筛选和反馈机制拿到成功结果。形成鲜明对比的是，本次“观察性实验”的结果说明level 5的用户明显能拿到更多成功结果。所以，实验结果并没有支持“人和agent是上下级”这种假设，甚至连初步证据都没给出来。

## 2. Agent今天被用来做什么，怎么用的

### 2.1 实验发现

#### 什么类型的任务是主流

Fig 1开宗明义，TOP3 的任务都早已经不是“顾问”、“咨询”类型，而是真刀真枪的干活

- fixing something broken 修理【软件】
- build something new 新造【软件】
- operating software 操作软件

上面前两行的【软件】是我加的，我没有证据，但以claude code的功能定位加上fix/build今天的能力范围，就算软件不是全部，也会是大部分。再看Fig 4右图对任务价值的估算，build、operate、fix 到2026年4月分别较2025年10月上升约43%、34%、32%，三条曲线几乎同步上行。也就是说，即便左图里fixing broken code的会话占比在下降，右图仍然显示这些更偏“干活”的任务本身正在变得更有价值；这和coding agent从单点修补走向更完整工作流的扩散是对得上的。

#### 高阶任务出现了，但是占比有限

回到Fig 1，其排名第7-9位的任务类型（占比3%、3%、2%）分别是

- orchestrating agents and pipelines
- analyzing data
- testing code

如果说“AI 工程师”这个职业存在，第七名的“orchestrating agents and pipelines”就一定会占他们工作的主要精力，然而，这种类型占总体使用只有3%。

分析数据和测试代码算不得什么新任务类型，但属于“深度任务”，毕竟分析数据背后的动机门槛 比 写出一个hello world demo要高很多。测试代码也是如此，不是为了“正确”、“稳定”，谁也没兴趣测试一个“看起来能跑的代码”。

#### 人是怎么在这些任务中使用agent的

对于上面这些需要“干活”的工作，“决策”和“执行”是怎么分工的？请看Fig 2. 这张图横轴以claude的视角，将工作分为10个桶，最左边是claude认为最需要人决策、几乎没有执行任务的，最右边是claude认为最不需要决策、只需要执行的。

在最左边的bucket，真实世界中只有20-30%的session由人给出了决策；然而，在最右边的bucket，真实世界100%的session都是完全交给claude。

这说明，1）人整体是懒的，能少动脑就少动脑，对于简单任务更是无脑全部交给agent去办；2）以当前agent来看，大部分复杂任务的用户是不合格的。只有20+%的情况下人给出了决策，剩下的时候盲目交给agent，“先跑个结果看看”，token烧了不少，拿不到任何有意义的结果。

### 2.2 讨论：Coding Agent的实际用户仍然没扩散出软件圈子、人还没有适应Agent

虽然当下的叙事是Agent扩散进入千行百业，各类社交媒体上“教学”内容汗牛充栋。但上述数据至少说明，截止到2026.04，Coding Agent的实际使用仍然高度受软件和数据工作场景牵引。本文写作于2026.06，情况会有变化吗，可能有，可能会逐步扩散的稍大一些。但是据我对周围人的观察，完全没有代码相关经验的用户，对于claude code / codex的畏惧感仍然没有下降。

我甚至可以用社交媒体上传播的“Anthropic工程师教你15min用claude”、“一个prompt让claude code产出高质量结果”这类内容作为论据：恰恰是因为大家既怕被时代甩下来，又怕自己学不会，才有这些卖课者 / charlatans的机会。这和两三个月之前很多人在某大厂楼下排队请人“帮自己”安装openclaw，之后再付费请人卸载openclaw没有任何区别。这样的人，就算下载了claude code / codex，他会长期支付每个月100-200 USD的费用吗，我不信。

这里“叙事”与“现实”出现了裂缝，这个裂缝混杂着两种不同的解释

- 通用Agent今天还不够强，如果足够强，大家就直接上手，没有畏惧感：是的，成立
- 今天的通用Agent路线可能只适用于“数理世界”（可被规则验证的世界），如果一个人的工作边界在数理世界之内：如给定spec的软件开发、数据分析等，那么Agent很有用；但如果在这个边界之外，无论是三教九流的哪一种，agent的价值还没有大到“让人们专门来学”的程度。如果真的是这样，“通用”这个词是要加上定语的。这个定语会决定对使用者的门槛、对模型外部“脚手架”的需求，甚至，不是模型+脚手架、而是定制化系统+模型，后者的业务中，模型只是一个可替换的通用智力基础设施。

当前的叙事当然倾向于前一种，但我坚持认为第二种解释是可能的。这不是乐观或悲观的问题，这是常识决定的：数理世界是一个人工规则构造的世界，Agent有可能学到最优解；真实世界是**动态、多主体**复杂运动形成的，且不说其开放性，仅仅是动态性就决定了哪怕你每时每刻都能实时更新LLM的全体权重，你也学不到下一刻才能形成的、新的、局部的新发现、新知识。

如果说上面这个叙事与现实的裂缝讲的是“通用”两个字的成色，那我们接下来退一步，在现在这种以软件圈子为主的专业用户条件下，看看agent对用户是不是“无门槛提效”，agent有没有适应人，人有没有适应agent。

在前面提到的“决策”和“执行”的分工分析中，数据说明“人整体是懒的，能少动脑就少动脑，对于简单任务更是无脑全部交给agent去办”。这本身没问题，发明agent就是要做这些事。问题是，真实世界用户的行为证明：没有那么多“简单任务”，很多任务是需要决策、计划、思考的。对于这样的“复杂任务”，人仍然是懒的，最复杂的任务分组中，人只在20%的session做了自己该做的事。这又是一个裂缝，同样有两种解释。

- 通用Agent今天还不够强，如果足够强，所有的任务都变成简单任务，人就可以懒下去。
- 通用Agent在复杂度上是有边界的，就像前面讲的适用范围边界一样。即便这些Agent背后的模型学完了任何一个人类工程师都不可能通读的海量代码，不代表agent能解决Linux作者面对的复杂架构问题，更不代表它能设计出下一个linux。这些复杂软件是真实世界在数理世界的投影，如果一个实体不能参与真实世界，就不能建模真实世界，那怎么可能设计出代码架构？

至少截止到今天，第一种解释没有说服我。

## 3. 反思

数据毫无疑问的证明了，今天的“通用Agent”可能适用于目标明确、反馈可验证、规则相对稳定的任务。

重要的是未来怎么样：面对“数理世界之外的大千世界”和“开放动态复杂系统”，没有任何证据能回答“通用Agent”是不是真的通用。换句话说，“通用Agent” / AGI这条路，到今天也没有一定能走通的证据。这与AGI定义模糊无关，只与“通用”这两个字有关。

我写下这句话之后，才发现自己说出了怎样一句离经叛道的妄言。如果“今天没有证据”变成“未来十年没找到证据”，那么

- 今天OpenAI和Anthropic在算力上的不计代价的CAPEX，很大程度是是基于“通用性”带来的巨大市场空间支撑的；一旦“通用性”没有那么通用，无论是模型厂的ARR，还是上游厂家的扩产，都难言确定性回报。
- 更要命的是，Physical AI，Biology AI等等，各行各业面对的此前几十年、甚至几百年都没攻克的技术难题，可能并不会因为AI就迎刃而解。资本市场对于“AI改变人类文明”的想象将成为无本之木。
- 更不存在因为AI就对人没有要求，在这篇研究报告里，对于软件这么干净的行业，人的差异都明明白白的体现出来；那么对于更复杂的行业，如果今天的教育在AI Hype下走几年弯路，那么人才从哪里来？

我不是反AI，但数据记录了事实，基于事实存在这种可能性，这是逻辑的必然。
