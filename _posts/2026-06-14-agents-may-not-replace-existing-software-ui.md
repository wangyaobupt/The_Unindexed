title: "Agent 未必能替代现有软件 UI"
---

最近一年，软件股票跌得很惨：以 Adobe 为代表，其实 MSFT 也差不多。市场上的叙事前后已经迭代了至少两个版本：

1）Agent 时代不需要软件，软件变成了一次性产品。

2）Agent 时代虽然还需要专业软件，但是定价逻辑变了。

第一种叙事已经被证伪，我不去讨论它了。

第二种叙事，让我引用一些讨论作为起点：

> 中年电竞选手 作者 06-12 16:06 · 新加坡
>
> 我觉得关键不是“软件会不会消失”，而是软件护城河会被重估。
>
> 过去软件是给人用的，所以 UI、用户习惯、培训成本、组织切换成本，都会形成很强的护城河。公司一旦用习惯了某套工具，即使贵、难用、臃肿，也不太愿意换。
>
> 但 agent 出现后，使用者开始从“人”变成“AI”。给人用的软件需要好 UI；给 AI 用的软件，命令行、API、结构化接口反而更优，因为 AI 不需要漂亮界面，只需要可调用、可组合、可自动化。
>
> 所以很多过去靠 UI、用户习惯、学习成本、组织惯性形成的超额利润，都会被削弱。
>
> UI 层会变薄，很多内部工具可以让 AI 按需求临时写；付费软件也更容易被 “agent + 开源软件” 替代；迁移数据库、CRM、报表系统这类过去很重的工程，也会因为 AI 的低成本劳动力而变得更容易。
>
> 所以 agent 不一定会消灭软件，但会消灭很多软件公司过去赖以收费的理由。
>
> 未来真正的护城河，可能不是“用户习惯用我”，而是底层能力、API、独占数据、可编排性，以及能不能嵌进真实业务闭环。

这一叙事合理吗？合理。

但一定如此吗？我想提出不同的看法。

UI 不是“给人用的”这么简单。

我，作为一个资深架构师，理论上现在写代码只需要 Claude Code，不需要 IDE 了，但我还是需要 VS Code 或者 PyCharm，因为我得看 Claude Code 生成了什么。“看”，或者叫“审阅”，或者任何其他名字，使得我还是离不开 IDE。是因为我是老登才会如此吗？不是。据我观察，小登们比我还依赖 IDE，他们甚至不习惯在 CLI 操作 Claude Code。说极端一点，你禁用 IDE 之后，我这个老登还能用 Vim，小登们大概率要抓瞎。

只要我用 IDE，UI、快捷键这一系列资产就还在，这是任何 Agent 抢不走的。为啥？这些 UI 不是某个产品经理的设计，而是工程师社区过去二三十年沉淀下来的“共同知识”，或者叫“文化”。

我再换个例子：QWERTY 键盘。从 90 年代我第一次接触电脑开始，就觉得这东西反人类。然后怎样呢？这个 UI（这也是一种 UI）已经存在了超过五十年，大概率还能再活五十年。

谁有资格定义某个专业软件的 UI 长成什么样子？只要这还被称为“专业”，就只能是这个专业的现有人员。所以，只要你还是需要为了重要场合（商业广告、答辩 PPT、融资需要的 BP）聘请设计师，那么设计师就是唯一有资格定义设计软件的人。只要承认这个假设，那么 Adobe 的 UI 比你想象的值钱。这个 UI 不是“给人用的界面”，而是“专业人员长期沉淀的责任边界”。

> 软件从来就不只是软件，而是建模真实世界复杂性的模型。
>
> 软件公司的资产从来不是代码，而是几十年里沉淀下来的那套世界模型。
