title: "与Agent的对抗：为什么70分很容易，90分却要几十轮？"

最近，我又花了 30 分钟修改一页 PPT。

不是从零开始做。Agent 几分钟就给了我一个 70 分左右的版本，我一开始很兴奋：过去需要一两天完成的工作，现在只要花几十分钟，甚至几分钟准备任务上下文，就能得到一个像模像样的结果。

但我想要的不是 70 分，而是 90 分。于是，我让它修改。第一轮之后，我发现了几个新问题；解释清楚，再改一轮，又出现几处新的不满意。有时它准确执行了我的字面要求，却破坏了另一处我没有说出口的东西；有时我以为自己已经讲得很具体，看到结果才意识到，真正重要的限制条件根本没有被我说出来。

我就这样和它来回了十几轮、几十轮。第一版只用了几分钟，后面的每一分却越来越难。在最近半年的 Agent 协同工作中，这个场景反复出现。直到又一次被修改折磨之后，我才想明白：70 分和 90 分之间，缺的可能已经不是知识和智能，而是通信。

这里的 70 分和 90 分当然不是某种客观测评，而是我的判断。区别在于：70 分的结果让我觉得“已经做出来了”，90 分的结果才让我愿意在一个重要场合真正使用，并且为它承担后果。

## 每改一轮，我反而看到更多不满意

进入修改阶段之后，每一轮都同时面对几个变量。

第一，我很难把需求里的每个细节都说出来。当我意识到自己必须逐条解释时，精力上已经做不到；但如果我只说一句“再改得好一点”，这句话连我自己听了都摇头。

第二，无论我的要求空泛还是具体，无论我面对的是哪一个最先进的模型，Agent 都会形成自己的理解。这一点很像人。无论我怎么表达，下属和学生也不可能在头脑里复制一个和我完全相同的版本。他们会理解我的话，但那始终是他们的理解。

第三，Agent 在真正动手时还会继续调整它对需求的理解。它需要写出能运行的代码，或者写出符合指南的项目申报书，于是就会在现实约束与我的要求之间做自己的平衡。

这些变量叠加起来，一轮修改之后，我往往只会发现更多“不满意”，而不是觉得“终于改好了”。我在此前的[《提效率山穷水尽，扩能力海阔天空》](https://wangyaobupt.github.io/The_Unindexed/2026/06/13/efficiency-hits-a-wall-capacity-opens-the-world.html)里记录过那次 30 分钟修改一页 PPT 的经历，但当时还没有想清楚，为什么第一版那么快，剩下的 20 分却那么慢。

这也不是我一个人的问题。我在网上认识的一位朋友说过，当一份 PPT 的好坏不是由自己决定，而是由领导决定时，用 AI 反而更累。因为他不但要向 Agent 表达自己的想法，还要表达他所理解的领导的想法。夹在他和领导之间的 hidden assumptions，本来就很难被完整说出来，现在却要再经过一层自然语言传给 Agent。

我也观察过社交媒体上反复出现的“一个提示生成网站”“几小时做一个游戏”。结论差不多：这些成果不忍细看。你但凡有自己的主见，就一定还要继续修改。流行叙事故意抹掉了这一部分，让人觉得生成就等于完成。

他们当然也可以说自己没有撒谎，因为对很多场景来说，一次生成的 70 分结果已经够了。但高价值场景不能接受这个标准。我的需求不是玩具。

## 70 分之后，问题从生成变成了通信

前 70 分，Agent 主要依靠世界知识和写作能力完成。需求的粒度很粗：写一份项目申报书，做一份投资 BP，或者搭一个可以运行的网站。它见过足够多相似内容，也知道这些东西通常应该长成什么样子。

但 70 分之后，每一次修改面对的都不再是一般意义上的世界知识，而是“我究竟想表达什么”。这些信息不存在于互联网，也不存在于模型参数里，只存在于我的脑子里。此时，人机协作的问题已经从“生成”变成了“通信”。

这不是 Agent 不懂写作。很多时候，它知道的写作技巧比我更多，也能举出更多案例。真正缺失的是：它不知道我到底想要哪一种表达，不知道哪些地方我可以妥协，哪些地方一个字都不能改。

我本科读的是 EE。当我重新用通信原理看这件事，问题就变得很清楚。

假设我脑中真正想要的结果是 $X$。我首先要充当信源编码器，把 $X$ 编码成一段自然语言消息 $m$；消息经过 CLI 或聊天框这个信道，交给 Agent 解码；Agent 根据 $m$ 重建出它所理解的目标 $\hat{X}$，再执行任务，生成结果 $Y$。我看到 $Y$ 不满意，继续发出下一条消息，形成反馈回路。

```text
X（我脑中的目标）
  → 人的自然语言编码
  → m（提示与反馈）
  → CLI / Chat 信道
  → Agent 的语义解码
  → X̂（Agent 所理解的目标）
  → 执行
  → Y（实际结果）
  → 人审阅后进入下一轮反馈
```

我不是要把审美和意图强行换算成多少 bit，也不是说自然语言这个物理信道的 Shannon capacity 不够。这里真正重要的是 $X$ 与 $\hat{X}$ 之间的失真，以及我要经过多少轮反馈、付出多少认知成本，才能把失真压低。

失真首先发生在信源编码。我脑中的许多要求是隐性的：我知道看到什么会不满意，却未必能在看到之前把它写成一条需求。把 $X$ 编成 $m$ 的过程本身就是有损的。不是我不愿意写一个更好的 prompt，而是有一部分信息在进入 prompt 之前就已经丢了。

第二层失真来自信道所保留的信息类型。聊天框只接收我主动写进去的自然语言。它看不到我盯着哪句话犹豫了十秒，看不到我删掉一整段实现细节，也看不到我把两个段落交换了位置。这些行为原本都携带信息，却在进入信道之前被直接丢弃。

第三层失真发生在解码。Agent 收到同一个 $m$，会根据自己的上下文和先验重建 $\hat{X}$。它对我的话有自己的理解，就像下属和学生也不可能在头脑中复制一个与我完全相同的版本。接下来，它还要在我的要求、工具能力和现实约束之间做平衡，最终生成的 $Y$ 与 $\hat{X}$ 之间又会多一层偏差。

自然语言在人与人之间之所以经常显得带宽很高，是因为接收者拥有大量 side information。我和同事每天见面。他写了一份项目申报书给我审核，我只要说“改得专业一点”“参考此前那份材料”，通常就够了。我不需要把背后的所有隐藏信息再传输一次，因为他知道我们过去做过什么、老板在意什么，也知道此前那份材料为什么有效。

同一个例子的反面，是我们读外国文学、古典文学时会觉得困难；换了一位新领导，合作也需要磨合。字面消息没有变得更短，真正缺失的是解码端的 side information。Agent 不是每天坐在我旁边的同事，它也不天然拥有我过去几年积累的上下文。

反馈当然可以逐轮修正误差，但现在这个反馈回路延迟很高。每次我都要先观察完整结果，再把不满意重新编码成语言，等待 Agent 解码和执行。更麻烦的是，一次局部纠偏还可能扰动原本正确的部分，于是下一轮不是简单地缩小误差，而可能产生新的误差。

这种情况下，要我一次说出“每一个细节需求”，对我是不近人情、不讲道理；要求 Agent 自动“善解人意”，同样是强人所难。

如果自然语言的有损编码和高延迟反馈是问题，有没有一种方法，不需要我先把所有想法翻译成语言？

## 别放弃既有工具的 UI

Word、PowerPoint 这样的软件 UI，长期以来被我误解为“给不会写代码的人用的”。现在我越来越觉得，它们真正的价值是：高带宽、低失真地表达你想要什么。

UI 的优势在于直接操作对象，而不是先逼迫你用语言描述操作。

在 Word 里，我不需要说“把第三自然段第二句话里的某个词删掉，再把标点符号改过来”。我看到这个词，用鼠标和键盘直接修改，眼睛马上看到修改后的句子。整个过程中，我根本不会费力思考“应该怎样用语言描述这次改动”。

对比一下两种流程：

```text
Word：
脑中的想法 → 鼠标与键盘 → 文档立即变化 → 眼睛看到结果

Agent：
脑中的想法 → 用语言描述需求 → LLM 理解 → LLM 执行修改
→ 文档发生变化 → 眼睛看到结果
```

第一条路径只需要几秒钟。第二条路径里，用语言描述可能要十几秒甚至几十秒，等待理解和执行又需要几分钟。更麻烦的是，只要 Agent 的理解稍微偏了一点，我就必须重新开始下一轮通信。

所以，我现在的解决方法是把旧工具的优势重新捡起来。

当 AI 写出 70 分的初稿之后，我不再试图只用对话框教它怎样逐句修改，而是回到 Word 或 PowerPoint，按照自己正常写文章、做材料的方式直接修改和批注。完成一轮之后，我再把整个版本交给 Agent，让它猜测我为什么这样修改，并基于它所推断出的意图，对全文做进一步调整。

表面上，我只是给了 AI 一份修改后的 Word 文档；实际上，我给原有的自然语言信道增加了一条新的旁路：编辑行为本身。

删除、替换、移动、批注和保留，是一种带宽更高的新语言。它们共同表达了我真正的意图，也给了解码端更多 side information。Agent 再从修改前后的差异中猜测我的 hidden assumptions。它仍然可能猜错，但至少我不必先把脑子里的每一个细节压缩成一句笨拙的指令。

## 真正需要优化的是 Interface

AI 在“生成第一版”这件事上已经足够好。限制生产力的关键正在从智能转向通信。

如果通信才是 70 分到 90 分之间的瓶颈，那么继续优化模型能力，并不会从根本上解决问题。模型更强，当然可以让第一版更接近我的要求，也可以减少一部分低级错误；但只要我的真实意图仍然只能通过一个狭窄的对话框传进去，后面的对抗就不会消失。

更强的模型、更长的记忆，以及能够持续观察人类操作的多模态 Agent，当然可能减少 $X$ 与 $\hat{X}$ 之间的失真，甚至改变我上面的判断。但要讲清楚这件事，恐怕需要另一篇文章。本文先不深入。

真正需要优化的是通信界面，也就是 Interface。

谁能让人的意图以更低的成本、更少的失真传递给 AI，谁才更有机会释放 AI 真正的生产力。
