过去一个季度，我陆续写下了几个关于 AI 的判断。今天重读这些文章，我想看的不是自己有没有“料事如神”，而是其中哪些判断经受住了现实的检验，哪些仍然缺少证据，以及我当时究竟是在判断一个具体产品，还是在判断更长期的结构。

## 更多 Agent 和更多 token，不会自动变成更多价值

3 月 28 日，我在[《时间窗口里的工作法：关于速度、价值与一种逐渐成形的判断》](https://wangyaobupt.github.io/The_Unindexed/2026/03/28/time-window-fomo-in-tech-transition.html)里写道：

> 如果没有质量控制，更多 Agent 和更多 token 并不会自动变成更多价值。它们当然可以制造出一种速度感、规模感、繁忙感，但这些感受本身，并不等于结果。

我当时进一步追问：既然原始数据已经留下了人在不同场景中决策的记录，LLM 也见过海量数据，为什么模型在真实 ICU 临床、自动驾驶这类复杂、动态、信息不完备的场景里，仍然做不了高质量推理？

我的判断是，真正决定结果的信号常常被噪音、时间碎片和隐式关联埋在里面。这类问题也不是一道有标准答案的题，而是要在不确定性中不断生成假说、累积证据、排除错误路径。它们没有数学证明或测试套件那样的机械验证标准，还掺杂着没有被正式写入数据的隐性约束。如果没有先把这些结构看清楚，后面无论堆多少算力，都可能只是在混乱里转得更快。

今天，我仍然 100% 肯定“更多 Agent 和更多 token 不会自动变成更多价值”。除了我在工作中看到的大量内部证据，Anthropic 6 月发布的研究[《Agentic coding and persistent returns to expertise》](https://www.anthropic.com/research/claude-code-expertise)也提供了一组外部证据：在 Claude Code 的真实使用中，用户在具体任务上的专业度越高，任务成功率和出错后的恢复率也越高。

这份研究不能直接证明我的整套解释，但它至少说明，模型能力并没有自动抹平人的专业判断。至于质量判断能不能最终靠“堆积算力”解决，我仍然倾向于三个月前的答案：不能。这不是因为我不相信 scaling law，而是因为复杂任务中的许多 hidden assumptions 只能从真实世界中获得；今天的 LLM 缺乏主动进入真实世界获取信息的内在动机——它没有生存和繁衍的压力。

## 人和 AI 之间，仍然是“师傅带徒弟”

4 月 20 日，我在[《AI 用于生产的瓶颈，正在从“写不出来”转向“控制不住”》](https://wangyaobupt.github.io/The_Unindexed/2026/04/20/the-bottleneck-of-ai-production-is-now-control.html)里，把人和 AI 的协作分成三类：

> “师傅带徒弟”模式：走得通，但不可能带来 10 倍效率，带徒弟的人一定会很累。
>
> “老板—顾问”模式：走不通，是老板的幻觉。
>
> “上级定方向、下级交结果”模式：很难走通，因为 AI 不怕人类所怕的社会惩罚。

三个月后，我仍然认为这个三分法囊括了我见过的组织和个人的工作方式。越是一线工作人员，“师傅带徒弟”越是主流；越是领导、教授和 CEO，越容易陷入“老板—顾问”的幻觉。所有人都想要“上级定方向、下级交结果”，但除了少数即用即抛、容错率极高的场景，大部分人还做不到。

Anthropic 的研究与“师傅带徒弟”的判断是相容的：专业用户更能给出方向、验证结果，并在 Agent 出错时把任务拉回来。我身边的学生也给了我同样的答案：即便给他们最新的 Agent，他们仍然不能完成自己尚不具备专业判断力的复杂工作，因为他们还没有能力做“师傅”。

“老板—顾问”模式则已经快成了笑话。我听一名博士生讲过一个很典型的场景：一位资深专家每天向 Chatbot 询问研究方向，得到的总是“这个方向大有可为”“那个突破指日可待”；可真正落地时，每个方向的问题都不是一个故事能讲清楚的。专家看着博士生，觉得 Chatbot 已经说得那么清楚，他们怎么还做不出成果；博士生看着专家，也觉得他根本不理解执行中的困难。所谓相看两生厌。

“上级定方向、下级交结果”的模式确实随着模型进步而改善了。但它仍然没有保证，也没有兜底。一旦“上级”面对的是自己承担不起的错误，他就必须进入细节检查，协作关系也随即退回“师傅带徒弟”。

## AI to C：两个还没有被市场检验的判断

5 月 11 日，我在[《被理解的经济价值》](https://wangyaobupt.github.io/The_Unindexed/2026/05/11/the-economic-value-of-implicit-understanding.html)里写道：

> 这一代技术真正不同的地方，是它可能把这种过去只能靠人际关系、雇佣关系和社会等级提供的理解能力，变成一种普通人也能使用的基础服务。它不只是替人回答问题，也不只是给人推荐内容，而是把“不要每一次都重新、完整介绍自己”变成一种可规模化的产品能力。

5 月 16 日，我又在[《AI to C 的成本是可解的》](https://wangyaobupt.github.io/The_Unindexed/2026/05/16/ai-to-c-cost-is-solvable.html)里提出，大多数 C 端请求没有想象中那么独特。真正可行的系统不应该让每个请求都走最贵的完整推理链路，而应该区分前沿认知和重复认知，把后者 cache 化、模板化，并交给分层路由和更便宜的系统处理。

这是过去一个季度里最缺少验证的两组判断。今天的市场仍然在拼模型智能、拼 AGI，AI to C 还很少被当成一门独立而成熟的生意来讨论。所以，“被理解”能不能成为普通人的基础服务，以及 C 端推理成本能不能通过缓存和分流被真正摊薄，我都还没有观察到足够证据。

不过，腾讯已经在公开推广 [WorkBuddy](https://www.tencent.com.cn/zh-cn/articles/2202350.html)，并把它放进个人与企业效率工具的产品组合里。也许再过十二个月，我们可以从产品使用和财务披露中看到腾讯对算力成本的真实判断。“无限需求”不见得真的无限，但现在下结论还太早。

## 对话没有取代专业软件 UI

6 月 14 日，我在[《Agent 未必能替代现有软件 UI》](https://wangyaobupt.github.io/The_Unindexed/2026/06/14/agents-may-not-replace-existing-software-ui.html)里写道，UI 不是“给人用的”这么简单。

我作为一名资深架构师，理论上写代码只需要 Claude Code，不再需要 IDE；但我仍然需要 VS Code 或 PyCharm，因为我得看 Claude Code 生成了什么。“看”，或者叫审阅，使我离不开 IDE。只要我还在使用 IDE，UI 和快捷键这些资产就仍然存在。这些 UI 不是某个产品经理一时的设计，而是工程师社区过去二三十年沉淀下来的共同知识。

同样，谁有资格定义一个专业软件的 UI？只要这件事仍被称为“专业”，答案就只能是这个专业里的现有人员。只要人们仍然会在商业广告、答辩 PPT、融资 BP 这些重要场合聘请设计师，那么设计师仍然有资格定义设计软件。Adobe 的 UI 不是简单的“给人用的界面”，而是专业人员长期沉淀的责任边界。

到目前为止，我没有看到反例。最近我还有一个进一步的观察：对话模式本身限制了沟通带宽，即便换成 CLI 里的 Agent 对话，其效率也远远比不上专业软件的 UI。Agent 可以改变操作软件的方式，却没有因此消灭人审阅、比较、定位和承担责任所需的界面。

## 我判断的是结构，不是产品

到目前为止，我的多数判断经受住了过去一个季度的检验。我认为原因不是“料事如神”，而是我的分析对象主要是结构，而不是具体产品。

如果盯着某个具体产品，今天的 Codex 显然已经能做三个月前做不了的长链任务；但从人机协作和责任划分的结构来看，它仍然只是一个“徒弟”：出了事需要师傅检查，而且很多错误屡教不改。

今天的主流叙事仍然不站在我这一边。真金白银的资本继续投向更多算力、更大规模和更高智能。唐杰在 7 月 11 日的一封[内部信](https://tech.ifeng.com/c/8uh0WghOyFp)里，把这次变革理解为技术革命对“智能上界”的抬升：谁能率先把上界推高，谁就能重新定义千行百业的能力边界；真正的 AGI，甚至应该具备创造“相对论”级原创知识的能力。

这套叙事符合逻辑，也激动人心，但我就是没那么敢全信。我相信我看到的“结构性问题”，和他看到的“智能上界”，可能同时正确。缺少任何一边，都无法实现他所说的那种创造相对论的能力。

他作为智谱的创始人，强调后者无可厚非，Dario 和 Sam 也是如此。主流的一线叙事很少正面讨论结构性问题，因为没有人知道怎样“通用地”解决它。于是，大家先用全社会的注意力和资本押注能力问题。

我没必要因为主流叙事的冷落就妄自菲薄。我们完全可以过一两年再看。
