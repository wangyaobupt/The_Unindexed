前两天 mythos 5 已经出来了，但社交媒体上的叙事还是在说“一晚上写出了红警”。我们逐渐进入了一种叙事陷阱：好像你要向另一个人描述一个 model 或 agent 厉害，就只有 benchmark 跑分 + “XX 时间内做了过去几个月的工作”。但工作不是为了“做出来”，是为了“能改变结果”。开发红警的团队在 PC 资源非常有限的条件下，写出了玩家能够在 2000 年前后的 CPU、Memory 配置下，通过 LAN 就能联机、稳定运行的程序。脱离开这几个约束条件，这个软件就什么也不是。

四月底我写过一篇[《写代码只是最窄的名字》](https://wangyaobupt.github.io/The_Unindexed/2026/04/29/not-coding-but-problem-solving.html)，其核心观点在于：

> coding agent 让一个不具备编程能力、但具备问题意识和逻辑思维的人，第一次有机会把自己的解决思路直接推向可执行状态。对专业程序员来说，从“自己写”到“带 AI 写”，是效率升级；对这类非专业用户来说，从“完全写不了”到“能做出来”，是能力跃迁。前者是速度变快，后者是世界变大。这两件事的性质不一样。

经过最近一个多月，我的观点更进了一步。因为我一直在一次次“掉坑-爬坑”的过程中使用“最先进”的 Agent 产品，不但没有如新闻所说“一键生成”，反而不得不付出巨大的认知和注意力成本，才能生成符合要求的成果。

> 如果进行严格计量，所谓“效率提升”很可能没有那么显著，甚至是伪命题；然而，从“完全做不了”到“能做出来”是实打实的，可被严格证明。

## 案例本身：30 分钟一页 PPT

我要写一份 BP。显然，这是一个足够重要的场景，就像你要去 pitch 一个大客户、毕业答辩等场景一样，对材料的质量容不得“差不多”，必须要做到“内心认可其达到我认知范围内的最好”。

我的工作流是这样的：

> 我写出一份草稿（PPTX 格式）
>
> → Claude Code 阅读整体，理解我的故事线  
> → 从第一页开始，Claude 阅读每一页（读 png），在满足故事线的约束下，提出改进意见  
> → 我审阅，给出反馈  
> → 在这一页需求锁定的条件下，Claude 调用 Codex，创建一页新的 PPTX。Codex 不仅负责写 PPT 页面，还负责生成必要的图像，用以插入 PPT 页面。  
> → 生成之后，Claude 做第一轮 proof-reading，如果不符合要求，打回去让 Codex 重写  
> → Claude 提交给我，如果我有疑问，则重新修改  
> → 重复上述过程，直到所有页面完成

在上述工作流下，每一页的时间成本大约在 30 分钟，个别页面甚至耗费了我 60 分钟。token 成本没计算，但我是 Codex 和 Claude Code 的 Pro subscriber。

## 案例讨论：为啥不能一键生成？

读者可能会自然地产生一个问题：

> 为啥在 AI 时代还要 30 分钟一页 PPT？是不是你太挫了？

让我为自己辩解几句：

- 为啥不用“一键生成 PPT”？恕在下愚钝，确实没能力用一段所谓“提示词”写出胸中锦绣。事实上，PPT 本质上是给人讲一个故事。我可以用几百字写清楚故事脉络，但用什么视觉元素讲，这些视觉元素怎么来、怎么排列，不同页面之间怎么分工，我既写不出来，也不认可这两家“最牛逼 Agent”默认给的结论。为啥我有资格“不认可这两家 AI 的默认推荐结果”？因为我是承担后果的人，Agent 不是。
- 为啥非得写 PPT，你不能让 Agent 写 LaTeX 吗？操作 PPT 是我花费几十分钟的直接原因。是的，这是削足适履。我知道 LaTeX，但我的老板、我的合作伙伴不一定知道。就算知道，他们也不一定有能力自己修改和编译。这份材料需要在不同人之间流转和修改，PPT 是事实标准，这是社会契约，我改不了。
- 那就不能让 Agent 写 LaTeX，再转为 PPT 吗？我当然这样做了，但每一次格式转换在视觉上都惨不忍睹。这种做法除了用作生成自己的 draft，并没有其他用。

> 那么，我到底从这个过程中得到了什么？如果 30 分钟一页是我自己手工也能做到的，AI 一点用都没有吗？

不是。如果没有 AI，我根本做不了这个水平的“设计”。

此前，为了关键场合的 PPT，我要么动用公司的设计团队，要么自己付费找设计师，去做“PPT 设计”。每次自己付钱都在几千元，需要等待两周左右时间。

更大的问题还不是钱，而是“不确定性”和“交易成本”。如果我和这个设计师没有充分的互相了解，在付钱之前我最大的疑问是：他能给我想要的漂亮结果吗？而设计师的内心 OS 恐怕是：这个甲方会不会要我反复修改，最后不给钱。几千块钱的 case，不值得比稿、投标、反复开会，所以双方都在“摸着石头过河”，最终导致我只敢去找我认识的人。这样的交易成本和小圈子限制，决定了我肯定找不到第一流的专业人员。

今天，用着 o 和 a 这两家的 Agent，我至少放心地知道它们具备 80 分水平的设计能力，且我可以事无巨细地交代我的需求、提出意见。大不了就是多花点 token，买不了吃亏，买不了上当，这还不够有吸引力吗？这就是我为什么在如此低的“效率”下依然用这么贵的 token 的原因。

> 用 token 标价对比我购买专业设计服务的门槛和不确定性，一点都不贵，太便宜了。

## 为什么“提效率”山穷水尽，“扩能力”海阔天空？

正如我写下了这一句：

> 为啥我有资格“不认可这两家 AI 的默认推荐结果”？因为我是承担后果的人，Agent 不是。

在“在乎结果”的场景下，承担后果的人才是社会契约的参与者。今天的 Agent 没资格签署社会契约，它还上不了桌。

因此，“提效率”的故事是死路一条。无论 o 和 a 的顶级算法研究员优化出多少倍的效率提升，到了真实场景，都会被现实用“是否担责”而退回去。这也注定了，如果一个 model 或 agent 的唯一卖点是“提效”，很快你就没有故事可以讲了。今天的公共论坛上，很多人已经体验不出来 mythos 5 比 opus 4.8 有什么差异，opus 4.8 与 codex 5.5 有什么差异。重点不在于谁更强，而是人们逐渐无法在脱离具体场景、责任的条件下，理解“什么叫做强”。在这个时代，一旦你无法被理解，你就失去了注意力。对于 o/a 这两家，失去注意力才是最灾难性的。毕竟，硅谷的投资人不怕你赔钱，怕你的故事不够大。

另一方面，如果我们把 AI Agent 视为每个人的能力扩展工具，那么其作用将非常强大。今天的我可以在 Codex 和 Claude Code 加持下得到 80 分的设计能力，我的实习生可以在加持下做出他自己完全做不了的数据实验，下了班的我可以用 Codex 读懂财报里的细节……这些场景将无穷无尽。过去，我们用“六边形战士”描述一个人，今天，只要你理解了 Agent，你也可以在一定层面上成为“六边形战士”。

> 不要再去幻想“一键生成”，诚实面对世界，投入必须的认知精力，用好这个时代的馈赠。
